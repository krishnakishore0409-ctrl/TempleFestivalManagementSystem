Known backend endpoint issues (7)
  • PUT update endpoints without /{id} in the mapping (e.g. @PutMapping("/festival/update") instead of @PutMapping("/festival/update/{id}")) still 404 when this UI calls them. Payment and Expense are already fixed — check the rest (Donation, DonationType, Event, ExpenseType, Festival, Item, Role, Unit) the same way.
  • Expense delete mapping (/expense/deleteId) is still missing /{id} — add it so @PathVariable int id has something to bind to.
  • ExpenseMapper.toResponse() never calls response.setExpenseName(...) — every expense's name comes back blank. Add that line.
  • ExpenseMapper.toResponse() sets response.setUnitName(response.getUnitName()) — that reads the DTO's own (still-null) field instead of the entity, so unitName is always null. It should be response.setUnitName(expense.getUnit().getUnitName()).
  • ExpenseService.getExpenseByEvent() sets summaryDto.setYear(event.getFestival().getFestivalId()) — that's the festival's ID, not its year. Should be event.getFestival().getFestivalYear() (the get-all version already does this correctly).
  • RoleService.roleDeleteId looks up and deletes from itemRepository instead of roleRepository — deleting a role currently deletes an item.
  • EventRequestDTO field is evenTime (missing "t") — the UI matches this so binding works, but worth a rename pass.
